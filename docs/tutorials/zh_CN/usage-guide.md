## 1. 产品简介

ALiang Gate（又称 Aliang Gateway / Nursorgate）是一款跨平台的高性能 AI 流量加速代理系统，支持 **深度模式（TUN 透明代理）** 和 **常规模式（HTTP 代理）** 两种运行方式。

### 核心能力

- **AI 流量智能路由**：自动识别并加速 OpenAI、Anthropic、Cursor、VS Code Copilot 等 AI 服务的流量
- **双模式运行**：TUN 模式可全局透明代理，HTTP 代理模式适合 CLI 工具手动配置
- **预置 API 密钥**：无需自行申请 OpenAI/Anthropic 密钥，登录后即可使用
- **跨平台**：支持 macOS、Linux、Windows
- **Web 管理面板**：通过浏览器管理所有配置和监控流量

## 2. 系统要求与下载安装

### 2.1 系统要求

| 平台 | 最低要求 |
|------|---------|
| macOS | macOS 12+（同时支持 Apple Silicon 和 Intel） |
| Linux | 主流发行版（amd64 / arm64），需要 root 权限使用 TUN 模式 |
| Windows | Windows 10+，深度模式需要安装 Wintun 驱动 |

### 2.2 macOS 安装

1. 从官方渠道下载 macOS 安装包
2. 将应用拖入「应用程序」文件夹
3. 首次打开时，如果系统提示"无法验证开发者"，前往 **系统设置 → 隐私与安全性** 中点击"仍要打开"
4. 双击启动应用

### 2.3 Linux 安装

1. 下载对应的二进制文件（`nursorgate-linux-amd64` 或 `nursorgate-linux-arm64`）
2. 添加执行权限：

```bash
chmod +x nursorgate-linux-*
```

3. 运行：

```bash
# 以前台方式启动
./nursorgate-linux-amd64 --config config.json
```

4. （可选）注册为系统服务：

```bash
sudo ./nursorgate-linux-amd64 service install --system-wide --config /etc/aliang/config.json
```

### 2.4 Windows 安装

1. 下载 Windows 安装包并运行
2. 如果弹出安全提示，选择"更多信息"→"仍要运行"
3. 安装完成后，应用会自动启动

> **注意**：Windows 用户首次切换到深度模式时，系统会自动安装 Wintun 驱动，此过程需要管理员权限。

## 4. 安装并信任证书

### 4.1 为什么需要证书

ALiang Gate 通过本地 MITM（中间人代理）方式识别和路由 AI 流量。为此需要在系统中安装并信任一个本地 CA 证书。

> 证书仅用于识别和加速 AI 流量，不会记录或传输你的任何数据。证书存储在你的设备上，不会被第三方获取。

### 4.2 安装步骤

1. 打开管理面板 `http://localhost:56431`
2. 在仪表盘左侧的 **网络状态** 区域，点击 **「重新安装」** 按钮
3. 系统会弹出授权提示，确认后开始安装
4. 安装完成后，证书状态应显示为 **「已信任」**

如果需要查看证书详情或手动操作，点击 **「详情」** 打开证书管理弹窗，可执行以下操作：

- **安装到系统**：将证书安装到系统证书存储
- **下载 PEM**：导出 PEM 格式证书文件
- **重新安装**：移除旧证书 → 重新生成 → 安装到系统（一键操作）
- **移除证书**：从系统中移除已安装的证书

### 4.3 证书状态说明

| 状态 | 含义 |
|------|------|
| 未找到 | 尚未生成证书 |
| 已生成 | 证书已创建，但未安装到系统 |
| 已安装 | 证书已安装到系统，但尚未被系统信任 |
| 已信任 | 证书已安装并被系统信任，可以正常加速 AI 流量 |

> 证书状态必须为 **「已信任」** 才能正常使用 AI 流量加速功能。

### 4.4 macOS 手动信任证书

如果安装后证书状态仍显示「未信任」，需要手动设置信任：

1. 打开 **钥匙串访问**（Keychain Access）
2. 在「系统」钥匙串中找到 ALiang 的 CA 证书
3. 双击证书，展开「信任」部分
4. 将「使用此证书时」设置为 **「始终信任」**
5. 关闭窗口，输入密码确认

## 5. 登录账户

### 5.1 登录流程

1. 在仪表盘左侧点击账户区域，或点击 **「立即登录」** 按钮
2. 在弹出的登录窗口中输入 **邮箱** 和 **密码**
3. 点击 **「登录」**

登录成功后：

- 弹窗自动关闭
- 账户区域显示用户名和套餐标签
- 认证状态显示「认证会话已激活」
- 解锁所有功能

### 5.2 会话保持

登录成功后，会话信息会保存在本地。下次打开应用时会自动恢复登录状态，无需重新登录。

### 5.3 未登录状态的功能限制

**未登录可用：**

- 证书管理（安装、导出、重新生成）
- 语言和外观设置
- 查看帮助文档

**未登录不可用：**

- 启动/停止代理
- 快速配置（Quick Setup）
- 客户配置修改（AI 规则、代理规则、客户代理）
- 用户中心（余额查看、充值、套餐兑换等）

## 6. 运行模式选择

### 6.1 深度模式（TUN）

深度模式通过创建 **TUN 虚拟网卡** 在操作系统网络层拦截流量，实现透明代理。

**特点：**

- 所有软件的 AI 流量自动被拦截和加速，无需逐个配置
- 支持 **Cursor 官方原生 AI 界面**
- 支持 **VS Code 官方原生 AI 界面**（Copilot）
- 也支持 CLI 工具（Claude Code、OpenCode、Codex 等）
- 全局生效，使用简单

**注意事项：**

- Windows 用户首次切换会自动安装 Wintun 驱动（需要管理员权限）
- 如果你的 VPN 也使用 TUN 模式，两者可能冲突；建议将 VPN 调整为 HTTP 模式
- 切换到深度模式时，系统会检测是否存在冲突的 TUN 虚拟网卡并给出提示

### 6.2 常规模式（HTTP 代理）

常规模式在本地启动一个 **HTTP CONNECT 代理**，监听在 `127.0.0.1:56432`。

**特点：**

- 适合 CLI 工具（curl、wget、Claude Code、OpenCode、Codex 等）
- 需要在各应用中手动配置代理地址
- 不支持 VS Code / Cursor 官方原生 AI 界面
- 适合需要精细控制代理行为的场景

**配置方法：** 在各应用的代理设置或配置文件中填写：

```
代理类型：HTTP 代理
地址：127.0.0.1
端口：56432
```

### 6.3 两种模式对比表

| 特性 | 深度模式（TUN） | 常规模式（HTTP 代理） |
|------|----------------|---------------------|
| 工作方式 | 虚拟网卡，系统层透明代理 | 本地 HTTP 代理，需手动配置 |
| Cursor 原生 AI | 支持 | 不支持 |
| VS Code Copilot | 支持 | 不支持 |
| CLI 工具（Claude Code 等） | 支持 | 支持 |
| 是否需要逐个配置 | 否，全局生效 | 是，需手动设置代理 |
| 端口 | 无（系统层拦截） | `56432` |
| 与 VPN 冲突 | 可能冲突（TUN 竞争） | 不冲突 |
| Windows 额外要求 | 需安装 Wintun 驱动 | 无 |

### 6.4 切换模式

1. 进入 **设置 → 系统设置**
2. 在 **运行模式** 区域，选择「深度模式」或「常规模式」
3. 确认切换

> **重要**：切换运行模式后，代理会保持停止状态，需要手动点击「启动代理」。

## 7. 启动代理

### 7.1 启动/停止操作

在仪表盘左侧面板中央，有一个大的 **电源按钮**：

- 点击一次：**启动代理**
- 再次点击：**停止代理**

代理状态显示在电源按钮下方：

| 状态 | 说明 |
|------|------|
| 代理已停止 | 代理未运行，无流量加速 |
| 代理启动中... | 正在启动代理引擎 |
| 代理运行中 | 代理正在运行，可以加速 AI 流量 |
| 代理停止中... | 正在停止代理 |

> 如果电源按钮被禁用（灰色），请检查：是否已登录、证书是否已信任、是否有强制更新未安装。

### 7.2 确认代理正常工作

启动代理后，可通过以下方式确认：

1. 仪表盘显示「代理运行中」
2. 在「状态」标签页中可以看到 AI 流量实时状态
3. 打开 Cursor / VS Code 等 AI 软件，尝试使用 AI 功能
4. 如果 AI 响应正常，说明配置成功

## 10. 使用 56432 端口配置 CLI 工具

### 10.1 端口说明

`56432` 是常规模式下启动的本地 HTTP CONNECT 代理端口。CLI 工具通过 `http://127.0.0.1:56432` 接入代理。

**工作原理：**

当 CLI 工具将请求发送到 `127.0.0.1:56432` 时，ALiang 会：

1. 接收到 HTTP 请求
2. 识别请求中的 Host 头
3. 将第三方 Host（如 `localhost:56432`）改写为对应的真实 AI 服务 Host（如 `openai.com`、`api.anthropic.com`）
4. 通过 Aliang 通道转发请求
5. 支持 OpenAI 和 Anthropic 格式的 API 请求

### 10.2 配置 Claude Code

Claude Code 使用 `ANTHROPIC_*` 环境变量进行配置。

**手动配置：**

```bash
# 设置环境变量
export ANTHROPIC_BASE_URL="http://127.0.0.1:56432"
export ANTHROPIC_API_KEY="你的API密钥"
export ANTHROPIC_MODEL="claude-sonnet-4-5"

# 启动 Claude Code
claude
```

**持久化配置（写入 shell 配置文件）：**

将以下内容添加到 `~/.bashrc`、`~/.zshrc` 或 `~/.bash_profile`：

```bash
export ANTHROPIC_BASE_URL="http://127.0.0.1:56432"
export ANTHROPIC_API_KEY="你的API密钥"
export ANTHROPIC_MODEL="claude-sonnet-4-5"
```

**使用 Quick Setup 自动生成（推荐）：**

参见 [10.5 快速配置功能](#105-快速配置功能quick-setup)。

### 10.3 配置 OpenCode

OpenCode 使用 JSON 配置文件。

**配置文件路径：** `~/.config/opencode/config.json`

```json
{
  "$schema": "https://opencode.ai/config.json",
  "theme": "system",
  "provider": {
    "openai": {
      "id": "openai",
      "name": "OpenAI",
      "type": "openai",
      "options": {
        "baseURL": "http://127.0.0.1:56432/v1",
        "apiKey": "你的API密钥"
      }
    }
  },
  "model": {
    "default": "openai/gpt-5"
  },
  "workspace": {
    "autoApply": false
  }
}
```

**使用 Anthropic 提供商时：**

```json
{
  "$schema": "https://opencode.ai/config.json",
  "theme": "system",
  "provider": {
    "anthropic": {
      "id": "anthropic",
      "name": "Anthropic",
      "type": "anthropic",
      "options": {
        "baseURL": "http://127.0.0.1:56432",
        "apiKey": "你的API密钥"
      }
    }
  },
  "model": {
    "default": "anthropic/claude-sonnet-4-5"
  },
  "workspace": {
    "autoApply": false
  }
}
```

> **注意**：OpenAI 格式的 `baseURL` 末尾需要加 `/v1`，Anthropic 格式不需要。

### 10.4 配置 Codex

Codex 使用 TOML 配置文件和 JSON 认证文件。

**配置文件路径：** `~/.codex/config.toml`

```toml
model = "gpt-5-codex"
model_provider = "openai"
approval_policy = "never"

[model_providers.openai]
name = "OpenAI"
base_url = "http://127.0.0.1:56432/v1"
wire_api = "responses"
```

**认证文件路径：** `~/.codex/auth.json`

```json
{
  "OPENAI_API_KEY": "你的API密钥"
}
```

### 10.5 快速配置功能（Quick Setup）

Quick Setup 可以为你自动生成上述 CLI 工具的配置文件。

**使用步骤：**

1. 确保已登录
2. 在仪表盘左侧点击 **「快速配置」** 按钮
3. 从预设模板中选择要配置的客户端：
   - **OpenCode** — 生成 `config.json`
   - **Codex** — 生成 `config.toml` + `auth.json`
   - **Claude Code** — 生成 `env.sh`（环境变量脚本）
4. 选择一个 API 密钥
5. 系统自动生成配置文件内容，可以预览
6. 点击 **「应用文件」** 将配置写入指定路径

> **重要**：填写目标路径时，请使用**完整绝对路径**，不要使用 `~`。例如：
> - 正确：`/Users/你的用户名/.config/opencode/config.json`
> - 错误：`~/.config/opencode/config.json`

## 11. AI 规则配置

AI 规则决定了哪些 AI 服务的域名流量走 ALiang 加速通道。

### 11.1 预设 AI 提供商

系统内置以下 AI 提供商规则：

| 提供商 | 包含域名 | 可编辑 |
|--------|---------|--------|
| **OpenAI** | `api.openai.com`、`cdn.openai.com` | 是 |
| **Anthropic** | `api.anthropic.com` | 是 |
| **VS Code** | `api.githubcopilot.com`、`*.individual.githubcopilot.com` | 否（内置不可修改） |
| **Cursor** | `*.cursor.sh` | 否（内置不可修改） |

每个提供商可以单独启用或禁用。

### 11.2 添加自定义域名

对于可编辑的提供商（OpenAI、Anthropic），可以添加自定义域名：

1. 进入 **设置 → 客户配置**
2. 在 **AI 规则** 区域，找到要修改的提供商
3. 点击 **「包含域名」** 右侧的「编辑」按钮
4. 在弹出的编辑器中，每行输入一个域名或 URL

**支持格式：**

```
# 完整 URL
https://api.openai.com/v1
https://chatgpt.com

# 纯域名
anthropic.com
claude.ai
```

系统会自动从 URL 中提取域名部分。

5. 点击 **「保存」**
6. 最后点击页面底部的 **「保存配置」** 提交到后端

> **隐私说明**：将第三方 API 放入 AI 规则不会泄露隐私。ALiang 仅根据域名判断是否为 AI 流量，充当透明代理，不查看或记录请求内容。

## 12. 自定义代理规则

代理规则让你可以为指定域名设置路由策略。

### 12.1 规则格式

每行一条规则，格式为：

```
domain,<域名>[,<动作>]
```

- **第一部分**：固定为 `domain`（或简写为 `domains`）
- **第二部分**：要匹配的域名
- **第三部分**（可选）：`proxy`（走代理）或 `direct`（直连），省略时默认为 `proxy`

### 12.2 配置示例

在 **设置 → 客户配置 → 代理规则** 中，输入以下内容：

```
# 以下域名走代理
domains,google.com
domains,discord.com
domains,github.com

# 指定直连
domain,example.com,direct
```

点击页面底部的 **「保存配置」** 提交。

## 13. 客户代理配置（上游代理）

### 13.1 何时需要

大多数用户 **不需要** 配置此项。只有在以下场景中需要：

- 你已有自己的 VPN 线路，想通过 ALiang 加速 AI 流量
- 你需要对特定域名通过特定代理出口进行智能路由

流量路径：

```
你的设备 → ALiang Gate → 你的 VPN（SOCKS5/HTTP）→ 目标服务器
```

### 13.2 配置步骤

1. 进入 **设置 → 客户配置**
2. 在 **客户代理** 区域，开启 **「启用客户代理」** 开关
3. 选择代理类型：
   - **SOCKS5**：如果你的 VPN 提供 SOCKS5 协议
   - **HTTP**：如果你的 VPN 提供 HTTP 代理
4. 填写服务器地址和端口，格式为 `IP:端口`（如 `127.0.0.1:1080`）
5. 如果代理需要认证，填写用户名和密码
6. 点击 **「保存配置」**

> 端口号必须在 1-65535 之间。

## 17. 流量镜像（高级功能）

### 17.1 功能说明

流量镜像功能可以在 TCP 层面对匹配指定域名的流量进行旁路镜像转发。镜像流量发送到指定的 HTTP 端点，不影响正常代理功能。

**特点：**

- 仅对路由到 Aliang 的流量生效，直连流量不经过镜像
- 镜像失败不影响正常流量
- 未配置时，开销仅一次 `nil` 判断，不创建任何 goroutine 或 channel

### 17.2 配置方法

在配置文件中添加 `traffic_mirror` 配置：

```json
{
    "customer": {
        "traffic_mirror": {
            "enabled": true,
            "target": "http://172.16.159.219:3000/mirror",
            "domains": ["api.openai.com", "api.anthropic.com", "*.cursor.sh"]
        }
    }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `enabled` | bool | 开关，`false` 时不产生任何开销 |
| `target` | string | 接收镜像数据的 HTTP POST 端点 |
| `domains` | string[] | 匹配域名列表 |

### 17.3 域名匹配规则

| 模式 | 示例 | 匹配范围 |
|------|------|---------|
| 精确匹配 | `api.openai.com` | 仅匹配 `api.openai.com` |
| 通配符 | `*.cursor.sh` | 匹配 `api2.cursor.sh` 等，不匹配 `cursor.sh` 本身 |
| 后缀匹配 | `openai.com` | 匹配 `api.openai.com`、`cdn.openai.com` 等所有子域名 |

**镜像数据格式：**

镜像端点会收到 HTTP POST 请求，JSON 格式包含 `flow_id`、`direction`（request/response）、`payload`（base64 编码的明文数据）、`timestamp` 等字段。

## 18. 常见问题（FAQ）

### Q: 点击启动代理后没反应？

1. 确认证书状态为「已信任」
2. 确认已登录
3. 检查是否有强制更新未安装
4. 在状态页面的实时日志中查看错误信息

### Q: 深度模式和其他 VPN 冲突怎么办？

建议将其他 VPN 切换到 HTTP 模式。如果必须同时使用 TUN 模式，AI 流量可能不稳定。切换深度模式时，系统会自动检测冲突的虚拟网卡并给出提示。

### Q: 为什么常规模式下 VS Code / Cursor 的原生 AI 不能用？

常规模式是本地 HTTP 代理模式，只适用于能够手动设置代理的 CLI 工具。VS Code 和 Cursor 的原生 AI 界面不支持手动配置 HTTP 代理，必须使用 **深度模式**。

### Q: 证书显示「未信任」但已安装？

1. 尝试重新启动应用
2. 在仪表盘点击「重新安装」证书（会执行完整流程：移除 → 重新生成 → 安装）
3. macOS 用户需要在 **钥匙串访问** 中手动将证书设为「始终信任」（参见 [4.4 节](#44-macos-手动信任证书)）

### Q: Quick Setup 配置文件写入失败？

1. 检查目标路径的父目录是否存在
2. 确保使用**完整绝对路径**，不要使用 `~`
3. 确保对目标路径有写入权限
4. 检查磁盘空间是否充足

### Q: AI 流量没有加速效果？

1. 确认 AI 规则中已启用对应提供商
2. 确认代理已启动（仪表盘显示「代理运行中」）
3. 深度模式下检查是否有 VPN 冲突
4. 常规模式下确认 CLI 工具的代理配置正确（`127.0.0.1:56432`）
5. 在状态页面查看 AI 流量实时状态是否有命中

### Q: 登出后配置会丢失吗？

不会。客户配置保存在服务器端，登出后重新登录会自动恢复。

### Q: 账户余额不足会怎样？

如果账户余额不足，代理服务将无法启动。可在仪表盘底部的「账户余额」区域查看余额，点击「充值」按钮进行充值。

### Q: Windows 深度模式安装 Wintun 失败？

1. 确保以管理员权限运行应用
2. 检查是否有杀毒软件拦截驱动安装
3. 手动下载 Wintun 驱动并安装
