## 1. 网络与组网

**T3 的长处是远程接入。** 它按 environment 保存地址、可用路由与会话。直连、SSH 端口转发、已有的 Tailscale 路径或 T3 Connect 可指向同一个环境。连接建立前核对环境身份，连接建立后可学习其它可达地址。每个客户端对同一环境有单一连接所有者。T3 Connect 数据流经过托管的 Cloudflare 隧道。对照版本中没有发现自研 NAT 打洞，也没有面向无公网设备的 DNS/TCP 下一跳入网产品。[T3 连接运行时](/Users/mac/MyProgram/AiProgram/vibe_on_phone/t3code/t3code/docs/internals/09_connection-runtime.md) · [T3 Connect](/Users/mac/MyProgram/AiProgram/vibe_on_phone/t3code/t3code/docs/internals/06_t3-connect.md)

**Aliang 的范围包括设备互访、文件直传、手选出口与代出网。** 现有 PhoneServer/agent 云端链路承担控制面，局域网及平台中继是可以复用的载体。已合入的安全批覆盖部分入口及接收侧缺陷。此前独立核验发现，跨网发起侧的拨号和配置分属 core 与 agent，这一块仍需验证和收敛。公开候选地址可作为提示，授权要按设备与账号身份执行，地址变化也不能放宽权限。[入口修复交接](/Users/mac/MyProgram/GoProgram/nursor/alianggate/docs/superpowers/specs/2026-11-25-ingress-hardening-mesh-chain-fix-handoff.md:160)

**迁移做法**

1. 借环境连接目录的思路，为设备记录稳定身份、候选地址、成功路径和回退原因。地址探测、身份核验、权限判断各有明确结果。具备多个载体时，先使用可用的受信路径，失败回到公网链路。
2. 借单一拨号所有权，把跨网载体的会话与凭据管理收在 agent 边界。按已采纳的乙′路线，先打通同账号异网设备的平台中继。冻结 mesh 跨网 UDP 打洞，文件传输按自己的链路独立验收。
3. 无公网设备 C 在可达的局域网选择有公网的出口设备 B，先完成局域网授权和 DNS / TCP 转发，再经 B 登录、注册和恢复业务。C 的第一跳可直接复用现有 LAN `mesh-exit`，因此 NET-02 可独立于跨网载体推进。App 能接收事件时按现有规则提示，App 下线时可在 B 查看待批准项，入号可走现有扫码兜底。
4. 手机局域网直连优先做文件收发及仪表盘访问，并验证账号与设备身份、加密、断点和回退。对话直传在同步契约稳定后再做。在用户选择直传历史不入云时，路径故障回云可继续新内容，直传历史何时补到云端取决于用户是否授权；产品上需明确这个边界。

**验收入口**是服务形态、`start` 形态、同局域网、不同网络、无公网搭桥、出口离线恢复。正常请求、未授权请求和撤销后的请求都要纳入。云端控制面继续可用，同账号访问边界和已确认的 DNS/TCP 范围由 NET 正本约束。[组网差距和现状核验](/Users/mac/.claude/projects/-Users-mac-MyProgram-GoProgram-nursor-alianggate/research/t3code-borrow-20261125/out/gap-mesh.md)

### D3 无公网搭桥的现有实现

- **已实现并通过针对性测试**：`ExitClient` 总是装配 LAN，跨网打洞独立装配。手工配置对端和身份后，可经 LAN 的 SSH `mesh-exit` 通道发 TCP、转 DNS。平台 HTTP 出口已有委托到已配置下一跳的入口，深度模式 DNS 已有规则驱动的转发。五项现有测试覆盖单跳 TCP、单跳 DNS、LAN 优先、平台 HTTP 改道和 TUN DNS。2026-11-26 在桌面本地重新运行，四个测试包均通过。[载体装配](../../../outbound/proxy/mesh/sshexit.go:101) · [平台 HTTP 委托](../../../processor/egress/egress.go:116) · [DNS 委托](../../../app/tunnel/mesh_assembly.go:115)
- **仍需完成的产品链路**：局域网首次申请、批准和互信材料交换；无公网设备的 agent 到 PhoneServer 主连接要经所选出口；现有本地 TLS / 443 代理路径也有未委托的分支。需要按常规 HTTP 和深度 TUN 的承诺分别验收覆盖范围。现有通路的测试与历史认证记录不能替代「无公网、仅可达 B、从零入号后业务在线」的真机验收。[agent 云端拨号](../../../app/http/services/agent_remote_ws.go:121) · [TLS 路由边界](../../../processor/tcp/handler.go:1666)
- **D3 已确认采用乙′。** 冻结范围限于 mesh 的跨网 UDP 打洞。LAN 搭桥继续承载 DNS + TCP，平台中继仍按 DEBT-02 验收，文件传输保留打洞能力并独立回归。若 C 既无公网，也无法在本地网络到达 B，需要先有另一台本地可达的出口。

## 2. 消息同步

**T3 把实时、恢复和缓存做成同一套协议。** 线程列表和详情分开订阅。恢复时客户端送出游标，服务端按有界历史决定续播或发快照。补齐期间的新事件仍进实时订阅，重合部分按序号去重。Web、桌面和手机共享订阅、事件应用与连接恢复逻辑。命令有稳定 ID 和持久回执，同一次发送可以安全重试。[T3 线程续订](/Users/mac/MyProgram/AiProgram/vibe_on_phone/t3code/t3code/apps/server/src/ws.ts:1057) · [T3 命令回执](/Users/mac/MyProgram/AiProgram/vibe_on_phone/t3code/t3code/apps/server/src/orchestration-v2/Orchestrator.ts:16535)

**Aliang 已有的数据可以复用。** agent journal 有消息顺序，PhoneServer 持久化会话、消息和控制状态，部分终态与审批具备回执或重放。当前手机恢复主要依靠缓存、账户快照和水位对账。既有消息序号在部分跨仓边界没有保留下来，控制状态也缺统一的恢复口径。正文增量一部分只在内存或合批后的账本中，PostgreSQL 的当前数据不足以构成每帧可重放的事件日志。[同步差距对照](/Users/mac/.claude/projects/-Users-mac-MyProgram-GoProgram-nursor-alianggate/research/t3code-borrow-20261125/out/gap-sync.md:190) · [同步交叉核验](/Users/mac/.claude/projects/-Users-mac-MyProgram-GoProgram-nursor-alianggate/research/t3code-borrow-20261125/out/verify-sync.md)

### 2.1 SYNC-01 测量的边界

- 回合内看用户发送到设备开跑、开跑后首段文字何时产出、产出后各端何时显示。统计按发起端、展示端和可用样本量分组。时间点不可观测时单独标记，特别是外部 TUI 内部产生内容但尚未写出时。
- 已有服务端时间戳可以复用作基线，服务端收到启动帧不能代替首段文字上屏。跨设备的时钟误差、采样覆盖率与超时样本都要显式记录。单端耗时可直接测量。
- SYNC-01 为 SYNC-02、03、04、12、13、14、15 的时间目标提供基线，也能发现流式合批造成的额外等待。状态能否恢复、是否重复执行，分别由 SYNC-05～07 的故障验收证明。
- 延迟采集先覆盖本次的四段链路和核心单端耗时。初版复用现有回合记录、结构化诊断与采样来生成 7 天查询和分位数，避免为每个流式帧增加生产数据库写入。

### 2.2 SYNC-15 TUI 和网页内容追平

现在 TUI 内容先经过约 10 秒扫描节奏，再受 hello 最小间隔与云端每会话详情冷却影响，手机进页面主要按云端账本对账。10、30、60 秒是各环节的代码参数，不能直接相加当作每次实际时延。网页仪表盘另取一组测量，验证它是否卡在同一链路。

1. **复现并记录四段。** 用无敏感内容、带唯一标记的短对话分别从 TUI 和网页发起。手机已打开页面与发完再打开各测一组。记录设备发现、服务端可见、手机收到及首个可见字符；同时记录 hello 时机会话冷却命中和重复刷新量。
2. **先交付进页追平。** 手机打开当前会话时，优先获取该会话已知的最新版本；若服务端版本无法确认是最新且设备可达，对该会话做限频、去重的轻量核对。设备离线或请求失败时仍能读缓存，恢复后走正常补齐。
3. **再交付已打开页面的实时更新。** 让 agent 报告已经读到的会话内容变化。PhoneServer 按会话合并与定向获取，手机只应用当前账号的合法变更。打开时的追平与实时接续按同一消息身份去重。TUI 可观测到的最小文本单位取决于其转录写入。
4. **验证原有保护。** 重跑当年大量 hello 与详情刷新叠加的故障条件，比较旧、新路径的 hello 频率、数据库锁等待、请求次数和积压情况。沿用退避、熔断、限流和 hello 的冷却，发生异常时回到原同步路径。

主要借鉴 T3 的「会话级订阅、正在看的会话优先、有界刷新」。SYNC-15 从设备发现起解决较上游的问题，SYNC-05 的游标负责补齐到达同步路径的状态。[SYNC-15 四段证据](../specs/2026-11-25-t3code-borrow-requirements.md#3-sync--消息同步)

### 2.3 SYNC-05～07 和跨端共享

- **控制态先收敛。** 利用已有消息序号恢复正文位置，为可观察的会话控制状态定义可比较的版本。连接恢复时以当前会话为单位补齐消息和最新审批/回合状态。游标缺失、过期、发现间隙或补齐超预算时用有界快照兜底。完整性优先于追求零快照。
- **实时订阅随后接续。** 保证补齐与实时流交界的并发事件可以被应用。先做 40 分钟不操作的运行测试，再加入 agent 断线期间启动的回合。上线按照 PhoneServer 向后兼容、agent/手机/网页逐步消费新契约的顺序。
- **安全重试走同一回执。** 用现有发送入口给同一次发送稳定身份。服务端受理后回包丢失、App 再次重试和服务重启作为三个独立场景验证，最终只能产生一条消息和一次实际运行。首版验收是手动安全重试，脱机持久发送队列另行排期。
- **先共享规则和夹具。** 手机和网页运行同一组重复、乱序、旧快照、新旧端兼容、撤销和已读到末尾的测试样例。稳定后抽出纯状态转换函数。Go 保持自己的 I/O 与执行实现，前端各自保留平台存储和生命周期。

## 3. 长任务过程和多 agent

**T3 的运行状态是一等记录。** 子 agent、委派和工作流步骤都能关联父任务与发起来源。用户能看到运行中发生的工具和请求，适配器可提供更细的原生能力。T3 还把大量的命令输出放到展开才订阅的旁路；主事件流保留足够的状态，便于低带宽客户端判断任务是否仍在进行。[T3 多 agent 研究](/Users/mac/.claude/projects/-Users-mac-MyProgram-GoProgram-nursor-alianggate/research/t3code-borrow-20261125/out/t3-multiagent.md) · [T3 性能预算](/Users/mac/MyProgram/AiProgram/vibe_on_phone/t3code/t3code/docs/internals/16_performance-regressions.md)

**Aliang 已有内置子 agent 执行能力。** 派发、排队、停止、追加指令及 journal 已经存在，网页和手机缺一部分数据与操作入口。Claude 的观测能先从实际可读取事件补齐，Codex 先按支持版本验证事件样本和控制能力。三内核各自能否观测、单停、追加和续跑，需要分别声明。[Aliang 多 agent 差距](/Users/mac/.claude/projects/-Users-mac-MyProgram-GoProgram-nursor-alianggate/research/t3code-borrow-20261125/out/gap-multiagent.md) · [子 agent 展示深挖](/Users/mac/.claude/projects/-Users-mac-MyProgram-GoProgram-nursor-alianggate/research/t3code-borrow-20261125/out/reqd-subagent-ui.md)

### 3.1 SYNC-16 可见过程

1. 内置内核支持的长工具，在实际开始、结束或取消时产出可验证状态。在首批覆盖的下载样例中，用户 1 秒内看到正在做什么和已用时；停止按钮明确是针对工具还是整个回合。未知总量仅显示阶段和耗时。
2. 并行设计已经确定活动记录和 AI 可选的 `progress` 工具。SYNC-16 复用其状态、版本与展示约定，并从内置工具执行边界自动报告状态，覆盖模型未主动调用 `progress` 的场景。相同原生任务只对应一张记录卡。[PhoneServer 跨设备耗时操作设计](/Users/mac/MyProgram/AiProgram/vibe_on_phone/AliangPhoneServer/docs/superpowers/specs/2026-11-25-unified-operation-progress-design.md)
3. 有增量输出的工具提供受控的输出预览，容量和刷新频率有界，失败原因脱敏。先验收「只等、无 stdout」「持续 stdout」「主动停止」三类，再拓展不同内核。不把工具参数、完整命令、令牌或原始敏感错误送入跨设备活动流。

### 3.2 多 agent 的三步交付

1. **可见、准确、可单控。** 先上 SUB-16、03、13、14、15，随后补 SUB-01、17、18。三任务并行时，等待审批、排队、运行三种状态都可见。仅内核声明支持时开放单控。一个任务停止后，另外两个与父任务继续运行。
2. **身份、工作区和预算。** SUB-05 为同一次派发提供稳定身份和父回合关联，重复投递不新增任务。SUB-12 在现有每回合保护之上加设备预算，避免多个会话同时打到上游。SUB-08 在有 Git 的项目对并行写任务做隔离，先用同名文件场景证明主工作区安全。跨内核委派由 RUN-08 的能力事实驱动，带有限上下文、原任务引用和权限上限。
3. **持久调度与跨机器。** 先做单机三任务并行与汇总的可恢复步骤，重启后已完成的步骤不重跑，失败待确认。此前的 P3 跨机委派随后进入规划，依赖同账号、分级授权、在线与撤销语义。远程任务重试必须能查到此前状态，权限约束由执行设备再次确认。

## 4. 回合编排与可靠性

T3 在提交命令时把状态、回执和待执行动作写到同一个边界。重启时区分与旧进程绑定的动作、可重试的动作、等待人的动作。某些恢复可以受限续跑。它还用能力声明指导界面和运行决策。[T3 编排与重启恢复](/Users/mac/.claude/projects/-Users-mac-MyProgram-GoProgram-nursor-alianggate/research/t3code-borrow-20261125/out/t3-orchestration.md:96)

Aliang 有 agent 先写运行收据、PhoneServer 记账、Goal 的启动裁决和终态回执。切入点是普通、定时、监听和仪表盘来源的覆盖以及旧审批、子任务、孤儿进程的收口。执行事实由 agent 提供，面向客户端的状态由 PhoneServer 发布，双方用可核对的运行身份和终态同步。[Aliang 编排差距](/Users/mac/.claude/projects/-Users-mac-MyProgram-GoProgram-nursor-alianggate/research/t3code-borrow-20261125/out/gap-orchestration.md)

- 首期沿用原 context 提供人工续跑。进程丢失、网络暂断和正在审批分别判定。旧进程的运行状态失效后，重放旧数据不能让它复活，审批和子任务各只结算一次。允许自动恢复的无人值守来源再评估连续中断熔断。
- 先保证内核审批实际行为，再收敛到共同决策规则。能力矩阵用支持、只读观测、不可用表达不同入口。后续排队使用 SYNC-07 的发送身份，顺序执行，前一项失败时先停在用户可见状态。
- Windows core 的 GetAdaptersAddresses 修复已合入本地 `1afe4bf5`。首轮试装仍有无转储复发，7 天稳定性验收尚未完成。RUN-11 的服务恢复负责可用性，RUN-12 的转储与复测负责确认是否还有内存写坏源，两者分别验。

### 5.1 首批开工顺序

- [ ] **先建立一个可复现样本。** 在三仓取相容版本，用一个此前两端均可访问的测试会话，分别从 TUI 和网页发出有唯一标记的消息。采集手机已打开和重新打开四个样本的同名时间点。固定网络、版本、内核和会话初始状态。首轮用样本时间线找瓶颈，再扩大样本统计 P50/P95。
- [ ] **SYNC-15 先交付进页，再交付实时。** 在 Go 的 `agent_vibe_digest.go` 及 PhoneServer 的 `helloDetailRefreshGate.ts` / `pageCache.ts` 验证发现与刷新边界，在 RN `VibeCodingSessionScreen.tsx` 验证焦点切换和消息呈现。先修复单会话打开时只看云端旧账本的问题，随后加设备变化到正在观看页面的更新。验收同时覆盖没有新内容、两个手机同看、旧端、离线、同一会话连开与高频 hello。灰度关闭新入口时，可恢复原追平路径。
- [ ] **SYNC-16 先交付内置长工具状态。** 与并行进度设计核对原生工具身份、任务标题与错误摘要，复用已有活动视图承载。用一个准备好总量的下载、一个没有输出的长工具、一个取消样例验证开始、耗时、终态与回合范围。再检查断线恢复后只有一条任务记录，失败原因可读，低频输出不遮住运行状态。
- [ ] **同时落实发布验证。** 用已合入的入口加固版本准备真机验证，按安装形态核对实际受限入口与原有合法访问。将测试数据与日志隔离纳入 DEBT-07，确保坏版本能被发布流程拦下。Windows RUN-12 使用含 WER 取证的同一版本做 7 天观察，出现复发时以转储更新归因。
