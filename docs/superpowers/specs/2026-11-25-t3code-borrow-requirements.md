## 0. 怎么读、怎么过

- 编号：`NET`、`SYNC`、`SUB`、`RUN`、`DEBT`。
- 优先级只表示严重程度：**P0** = 安全或正确性问题，或每天都在撞；**P1** = 本季度；**P2** = 排后面；**P3** = 等前置成熟。「前置」单独标，不占优先级。
- 状态：待做 / **在途**（分支上已有代码）/ 待拍板 / 待评估。
- 规模：S ≤ 3 人日，M ≤ 2 人周，L 更大。只读走读后的估计。
- **灵敏度不以鲁棒性为代价**：任何让同步更快的改动，都不得削弱退避、熔断、限流这类保护机制。
- 过审顺序：NET → SYNC → SUB → RUN → DEBT → 快赢清单。每条给结论：接受 / 修改 / 砍掉 / 延后。

## 2. NET · 组网与互访

**这一版按你定的原则组织**

- 公网云端链路永远是兜底。组网是新增的网络选择，不是替换。
- 组网主要服务 aliang-peer 和文件传输；agent 控制和 AI 问答默认仍走公网。
- 没有公网的内网设备，主动搭桥到一台出口设备；下一跳由用户手选；搭上之后业务流量和 AI 流量自动经下一跳出去。
- 访问边界：同账号设备不论网络环境都能互访；不同账号不能。
- 自动路径规划不做。

## 3. SYNC · 消息同步

**「不够灵敏」是五段不同的问题叠在一起**（全部有代码位置，详见归档的 `reqd-sync-latency.md`，共 76 条延迟源）

1. **开跑之前**：agent 的读循环是串行的，开跑前同步做一次公网请求（每个项目每分钟一次，上限 3 秒），这段时间点停止也要等；订阅时在读循环里整份读 journal；终端里开着 TUI 时，每个回合固定先等 3 秒。
2. **流式上屏**：云端 40 毫秒、手机 100 毫秒两级合批，每个突发的第一帧也等满，首字固定多等 140 毫秒；上屏上限每秒 10 次。
3. **恢复**：连接已死要 25–50 秒才发现；重连退避最长 30 秒，回前台不清零；回前台一律整表重拉；一次重连触发两次刷新，每次 hello 也触发。
4. **结构**：服务端每个 agent 连接只有一条串行链；每个连接 64 帧的队列溢出就断开；限速桶超限的帧被静默丢弃。
5. **网页仪表盘**：没有存活探测；重连预算只有 2 次；每帧两条日志；长回答越写越卡。

**关于打点的更正**：v1 写「全链路没有任何延迟打点」不准确。服务端已有三段慢样本环（无人读取）和每回合 7 个时间戳（手机不消费）；缺的是内核产出、首字、客户端上屏三个点，以及跨机器的时钟对齐。

| 段 | 机制 | 节奏 |
|---|---|---|

## 4. SUB · 子 agent

**现状一句话**

我们不缺子 agent 的执行能力——派发、并行、排队、单停、续跑、落盘，后端都齐——缺的是「看得见、看得清、管得着」。深挖的结论更具体：**三端的传输都不慢**（云端对子 agent 帧内联推送、手机 100 毫秒合批），慢在「事件何时产生」和「数据走哪条通道」。

**「展示得不够好」具体是这些**

- 「当前步骤」永远滞后一个工具：工具跑完才更新；等审批时没有任何状态，看起来像停在上一步。
- 看不到它在写什么：内置内核的子 agent 文本没有出口；Claude 的文本帧到了 agent 就被丢。
- 并行派同类型的子 agent，分不清谁是谁：帧和详情里都没有任务文本。
- 运行中看不到已用时和 token：数据在帧里，两端都丢了。
- 状态词不准：入口条把失败和中断算作「已完成」；被停掉的显示成失败或完成；没有「停止中」。
- 电脑上发起的会话，手机在运行中收不到子 agent 的帧；手机上运行中打开子 agent，经常是「详情不可用」或过时内容。
- 网页一打开面板，运行中子 agent 的实时字段就被清空。
- 网页面板是全屏遮罩，看子 agent 就看不了对话；两端都没有「正在跑的子 agent」的全局入口。

**两条实现约束**（来自深挖，写在这里免得设计时踩）

- 相位枚举在云端、手机 transport、手机 model 三处是白名单拒绝，新相位会被旧端静默丢弃。「等待审批」「停止中」「重试中」必须做成挂在 `progress` 上的可选字段。
- 子 agent 的文本增量不能搭现有 `ai.subagent` 帧的便车：云端对每条这种帧做一次数据库写入。要照「思考」的模板另开帧型。

## 6. DEBT · 技术路线与历史包袱（减法清单）

**先说组网代码的体量**：自建组网数据面约 **8,900 行非测试代码**（占全仓 5.8%）加约 **16,700 行测试**，其中打洞占 39%。11 月的提交里有 20% 碰过这些路径，而跨网两条腿从未在真机上承载过流量。云端的控制面与自建数据面是单向依赖：数据面借用控制面四样东西，控制面不依赖数据面——冻结或删除数据面，控制面只需摘掉约 100 行。
