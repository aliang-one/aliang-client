# 托盘面板样式设计（自研托盘 · 视觉与交互规格）

- 日期：2026-11-26
- 状态：样式已与用户逐节确认（三方案对比 → 方案 A 定稿 → 六点细化 → 交互原型验收），待 spec 评审
- 性质：**本文档只定样式——视觉、信息架构、交互契约；不含任何实现**
- 配套产物：交互原型 `docs/superpowers/specs/tray-menu-style-mockups.html`（单文件 HTML，所有数值与本 spec 一致，可交互验收）
- 上游依赖：实现底座与平台可行性见《托盘替换调研》`2026-11-26-tray-replacement-research.md`；本文档是该调研「阶段 2（左键富面板）」的视觉与交互输入
- ⚠️ 已知功能缺口：**endpoint 区块依赖 LLM endpoint manager（`2026-11-25-llm-endpoint-manager-design.md`，设计已定稿、实施未完成）**。该区块按目标形态先行定稿样式，落地时必须带降级策略（见 §4.4）

## 1. 形态与触发

- **单一自绘弹出面板**：点击托盘图标弹出（**不区分左右键**，两键弹同一个面板）。不是系统原生菜单——原生菜单画不了纯图标按钮，且 macOS 27 默认隐藏菜单项图标。
- ⚠️ 本条**有意取代**调研报告 §0 推荐的「右键永远保留原生菜单兜底」双形态：本设计是单形态。面板崩溃/不可用时的兜底（是否保留原生菜单代码路径）归实现计划与功能会话拍板，本文档不做实现承诺。
- 面板宽 **340px**（设计稿基准；实际实现可按平台 DPI 缩放），高度随内容自适应，圆角 **16px**。
- 材质：系统毛玻璃打底——Windows 用 DWM 亚克力圆角（22621+），macOS 用 NSGlassEffectView / NSVisualEffectView；面板前端只做半透明底色，模糊交给系统材质层（Win: `backdrop-filter: blur(28px) saturate(1.4)` 等效值，macOS 由 NSVisualEffectView 提供）。
- 失焦即收起（跟随系统弹出面板惯例）；弹出锚定托盘图标（实现层细节归调研报告，本文档不管）。

## 2. 信息架构（从上到下六个区块）

```
┌────────────────────────────────────┐
│ ① 状态头部    logo + 状态 + 副标题 + 状态点 │
│ ② 传输行      [▶/⏹ 启停合一] [↻] [常规|深度]  │
│ ③ AI 加速     总开关行 + provider 图标行      │
│ ④ ENDPOINT    Anthropic 组 / OpenAI 组      │
│ ⑤ AI AGENT    每内核一张卡片（24h 统计）      │
│ ⑥ 底部动作行   版本 · 仪表盘 · 设备互访 · 退出  │
└────────────────────────────────────┘
```

| 现菜单项 | 去向 |

| Quit | ⑥ 底部「退出」 |
| 设备互访 | ⑥ 底部「设备互访」 |

## 3. 状态矩阵

| 状态 | 状态头 | 传输行 | 其他 |
|---|---|---|---|
| 运行中 | 绿点脉冲 +「代理运行中 · 深度模式 · 127.0.0.1:56432」 | 停止态（红 ⏹ 高亮）· 重启可用 | logo 品牌绿渐变 |
| 已停止 | 灰点 +「代理已停止」+「下次启动 · ××模式」 | 启动态（绿 ▶ 高亮）· 重启禁用 | logo 灰化渐变 |
| 启动中 / 停止中 / 重启中 | 头部状态点换成 13px 琥珀 spinner + 文案「正在启动/停止/重启…」 | 主按钮显 spinner + 同款文案（启动中/停止中/重启中），**三控件全禁用** | — |
| 出错 | 红点 + 错误摘要（如「内核无响应」） | 启动恢复可用 | 点错误行跳仪表盘日志 |
| 未登录 | 琥珀点 +「未登录，原因见状态行」 | 三键全禁用 | 沿用现有「未登录不能启动」决策，原因由状态行承载 |
| AI 加速关 | 不变 | 不变 | provider 行与 endpoint 区降透明（0.35）+ 锁交互 |
| agent 空闲 | — | — | 卡片只显「空闲 N · 24h 共 N」芯片，无活跃芯片 |

语义色约定：绿 = 运行/激活/健康；红 = 停止动作/错误；琥珀 = 过渡/警告/退避/未登录；灰 = 停止/未检测/禁用。

## 4. 各区块规格

### 4.1 状态头部
- 左：34×34 圆角 10px logo（品牌绿渐变 `#2fd96e → #17a84c`，停止态灰化 `#9fb2a6 → #6e8277`）。
- 中：主标题 13.5px/700；副标题 11.5px，muted（监听地址、模式、上次运行时间等一句上下文）。
- 右：8px 状态点（语义色 + `pulse` 2s 呼吸；过渡态换成 13px spinner）。

### 4.2 传输行
- **启停合一按钮**（核心交互）：一个占位按钮，**停止态 = 绿 ▶「启动」**（`--brand-dim` 底），**运行态 = 红 ⏹「停止」**（红 13% 底 + 红描边 inset）。图标 + 语义色双编码。高 38px，圆角 11px，12.5px/700 文字。
- **重启按钮**：38×38 方形图标钮，仅运行态可用（停止态 0.35 透明禁用）；点击时图标自转。
- **模式 segmented**：占传输行剩余宽度，「常规 | 深度」，选中项白底浮起（深色模式高亮浮层）。运行中切换的语义（是否热切换）归功能会话拍板；原型按热切换演示，停止态切换仅影响下次启动。拍板时注意调研报告 §3.3 的已知隐患——现有 SwitchMode 会停掉运行中的代理且不再拉起，热切换实现不得复刻该行为。
- 一行三控件，间距 8px，左右边距 12px。

### 4.3 AI 加速行 + provider 图标行
- 总开关行：⚡ 图标 +「AI 加速」+ switch（32×19，圆角胶囊，品牌绿 on 态）。
- **provider 图标行**：图标池 = 平台可检测的 provider 家族 + 预留位。当前池：**Anthropic、OpenAI、Cursor**（可检测）+ **Gemini、Grok**（预留，标「暂不支持检测」）。
  - 默认全灰（30×30 圆角 9px，灰字图标）；**平台检测到哪家使用 → 点亮该家**（深色文字 + 绿描边 inset 1.5px + 右下角 9px 绿色状态点，弹性缩放出现）。检测驱动，**不可手动点亮**。
  - 行尾 muted 计数「检测到 N / M」（N=已点亮，M=可检测家数，预留位不计入分母）。
  - 点击图标：显示该 provider 检测详情（toast / popover，实现层定）。
  - AI 加速关：整行降透明 + 锁交互 + 行尾文案变「AI 加速已关 · 图标全灰」。
- 供应商逐行明细（延迟、模型名）**不上托盘**，留给仪表盘——托盘只表达「谁在被使用」。

### 4.4 ENDPOINT 区（⚠️ 依赖未完工的 endpoint manager，降级策略必带）
> 本区块展示与交互按 endpoint-manager 设计目标形态先行定稿。**实现时若 registry 数据源不可用（功能未上线/未配置任何 endpoint），整区不渲染**（不留空壳、不留「建设中」占位）——这是降级策略，不是可选项。

- 按协议族分组：**Anthropic 组 / OpenAI 组**（对应 `protocol_anthropic` / `protocol_openai` toggle；一个 endpoint 同时开两个 toggle 则同时出现在两组）。
- 组头（常显，无论展开与否）：协议图标 + 组名 + **当前激活 endpoint 名**（10.5px muted，130px 截断）+ chevron。
- 点组头展开/收起：chevron 旋转 180°，列表 `max-height` 0→200px 过渡 0.25s。
- 列表项：单选 radio 语义——14px 圆形勾选圈（选中 = 品牌绿实底白勾）+ endpoint 名（11.5px/600，截断）+ 优先级徽标（P1/P2，绿描边 ghost）。
- **优先级徽标映射**：endpoint-manager 的整数 `priority`（默认 50，越小越优先）在组内按升序排名映射为 P1 / P2 / P3…；`auto_group=0`（不进 auto 池）或未设优先级的显示「—」。
- **不可用 endpoint 的渲染**：`health_status='cooldown'`（含 429 专用冷却）→ 置灰（0.55 透明）+ 琥珀「冷却 Xm」徽标；**托盘 v1 拍板：`rank≥1` 的冷却行可点击激活（放行且不清零冷却，激活后行仍显示冷却徽标直至懒恢复；激活会把同协议组内其余 `auto_group=1` 且非 builtin 的 enabled 行互斥置 0，非池行与 builtin 不动）**；`health_status='disabled'`（摘除）→ 同款置灰 + 琥珀「已摘除」徽标，`rank≥1` 时不可选（点击 toast「已摘除的行请先在仪表盘恢复」零请求）；**`rank=0` 行（含冷却/摘除形态）一律先走非池闸**——本地 toast「该行不支持在面板钉选，请在仪表盘操作」零请求（面板 rank 闸先于状态闸，与后端 ActivateInGroup 的拒绝序同构；rank 池口径缝隙见钉选计划挂账）；`enabled=0`（用户手动停用）→ **不渲染**（用户刻意停用的不出现在托盘，管理归仪表盘）。
- **单选即激活**：点击候选项立即切换该组激活 endpoint（勾移动 + 组头 g-current 更新 + toast 反馈）。实现层注意：此交互与 auto 组「按优先级 failover」是两种调度语义，托盘单选 = 将该组流量钉到选定 endpoint；如何兼容 auto 池由功能会话对齐，本 spec 只定展示与交互。
  - **2026-11-27 落地裁定（钉选增量）**：v1 实现为「组内互斥激活」——点击 `rank≥1` 且非 disabled 的行 = 该行 `enabled=1`、同协议组内其余 `auto_group=1` 非 builtin 行 `enabled=0`（builtin 兜底行不参与互斥）；`rank=0`（builtin/`auto_group=0`）行与 disabled 行点击仅本地 toast、不发请求；点击已是勾选态的行 = 空操作（避免互斥连带关停同组冷却行）；在途单飞；乐观勾移 + summary 回读确认，失败/未确认回滚。勾选态按行字段推定（`rank` 最小的 ok 池行；池全冷却回落 builtin 名字），不用 `current==name` 名字匹配（重名行不撞车）。toast 带组名上下文（「组 → 名」）。二期 endpoint-phase2 §5.6（激活迁移清零）合入后自动升级，托盘零改动。

### 4.5 AI AGENT 区
- 分区标题「AI AGENT · 24H」。
- 每个探测到的 AI 内核一张卡片（圆角 12px，内边距 9×11）：🤖 图标 + 内核名 + 右箭头。
- 卡内三枚统计芯片（10.5px/600）：`活跃 N`（绿底）· `空闲 N` · `24h 共 N`；活跃为 0 时不显示活跃芯片。
- 点击卡片展开 24h 会话明细：每条 = 状态点（活跃绿带光晕 / 空闲灰）+ 会话标题（11px/600，截断）+ 来源与相对时间（10px muted，「网页 · 2 分钟前」）。再点收起。
- 数据语义：「24h 内发生的对话」「正在活跃的」「空闲的」；来源维度（网页/终端/手机）沿用现有会话数据。

### 4.6 底部动作行
- 左下：版本号 10.5px muted tabular-nums（如 v1.1.124）。
- 右侧三键等宽：仪表盘 / 设备互访 / 退出。前两键灰字 hover 浮底；**退出键 hover 变红**（危险语义），点击弹退出确认（沿用现有 Quit 行为）。

- 字号阶梯：13.5（头部主标题）/ 13（面板基字）/ 12.5（按钮、agent 名）/ 12（区块行）/ 11.5（副标题、endpoint 名）/ 11（会话标题）/ 10.5（徽标、分区标题、muted）/ 10（会话 meta）。字重：主标题与按钮 700，正文 600，辅助 400。

## 6. 交互契约（实现时的映射规格）

1. **启停合一**：点击 → 过渡态（琥珀点「正在启动/停止…」、传输行三控件全禁用、主按钮显 spinner+文案）→ 约 1.1s 后到达目标态。过渡期间重复点击无效（防抖）。
2. **重启**：仅运行态可用；图标自转 + 同款过渡态「正在重启…」→ 回到运行态。
3. **模式切换**：即时切换选中态 + toast；运行中切换是否热切换由功能会话拍板。
4. **AI 加速开关**：关 → provider 行与 endpoint 区降透明（0.35）+ 锁交互；开 → 恢复。toast 反馈。
5. **provider 图标**：点亮由检测驱动；点击查详情（toast/popover）。
6. **endpoint 组**：组头点开展开/收起；列表项单选即激活（勾移动 + 组头 g-current 更新 + toast「Anthropic 组 → glm-coding-plan」；v1 组头名更新为瞬切，淡入过渡留作样式打磨）；冷却项可激活（v1 拍板：放行且不清零冷却，徽标持续至懒恢复——覆盖本行此前「不可选」）。
7. **agent 卡片**：点击展开/收起 24h 会话明细。
8. **底部三键**：外部动作——仪表盘开浏览器、设备互访开互访页、退出弹确认后退出。
9. 通用：所有破坏性/外部动作均有 toast 或确认兜底；面板内不做页面跳转，重操作（endpoint 增删改、会话管理）一律引导去仪表盘。

## 8. 明确不做（本 spec 范围外）

- 不定实现技术栈、进程模型、锚定与失焦行为（归调研报告与实现计划）。
- 不做 provider/endpoint 的增删改查界面（托盘只读 + 切换；管理归仪表盘 EndpointManagerSettings）。
- 不做会话内容浏览、图片、审批流（重交互归仪表盘聊天页）。
- 不定 toast/popover 的最终形态（原型用 toast 演示，实现层可选气泡或 popover）。

## 9. 验收口径

- 交互原型 `tray-menu-style-mockups.html` 已验收：覆盖运行中 / 已停止 / 三种过渡态的全部交互（§3/§4/§6 数值逐项一致）。**出错与未登录两态仅在 §3 文字层定义**（原型未实现该两态分支），实现计划以 §3 文字为准，装机后走查补验。
- 实现后的面板在深浅两色下所有状态（§3 七态）可走查。
- endpoint 数据源缺失时整区不渲染（§4.4 降级）。
- 零外部图标依赖（全部内联 SVG）。

## 10. M2 实现备注（2026-11-28）

实现层对本 spec 的三点落地备注（M2 收口批，Task 16）：

1. **豁免项定案（v1 缩减项的落点）**：
   - 错误行「跳日志」深链 v1 = 打开仪表盘根页（不做日志页深链路由，归 M 后续）；
